# AWS Resource Inventory

This document lists the major AWS resources that power the **Personal Video Streaming Service**. It describes the specific role each service plays in the architecture and how they contribute to a "Production-Ready" streaming experience.

## 1. Distribution & Content Delivery

| Resource | Logical ID / Name | Role in the System |
| :--- | :--- | :--- |
| **CloudFront** | `StreamingDistribution` | The "Global Storefront." Serves as the CDN for videos, thumbnails, and the Android APK. It ensures low-latency streaming and high-speed downloads worldwide. |
| **Origin Access Control (OAC)** | `StreamingOAC` | The "Security Guard." The modern standard for securing S3 buckets. It ensures that content is *only* accessible via the CDN and never via direct public S3 links. |
| **Edge Function** | `RewritePath` | The "Path Router." A lightweight CloudFront function that rewrites incoming requests (e.g., `/download/latest.apk` -> `/latest.apk`) to keep S3 bucket structures hidden from the user. |

## 2. Serverless API (BFF)

| Resource | Logical ID / Name | Role in the System |
| :--- | :--- | :--- |
| **API Gateway** | `StreamingApi` | The "Front Desk." Provides a secure, RESTful entry point for the Android app. Handles CORS, request routing, and throttles incoming traffic. |
| **Lambda (BFF)** | `GetCatalogFunction` | The "Orchestrator." Performs "Late Binding" of URLs—fetching logical keys from DynamoDB and transforming them into active CloudFront links at runtime. |
| **Lambda (Telemetry)** | `LogPlayEventFunction` | The "Data Collector." Receives playback events from the phone and emits high-granularity EMF logs into CloudWatch for business intelligence. |
| **DynamoDB** | `VideoMetadataTable` | The "Source of Truth." A NoSQL table storing video metadata (Title, Genre, Year) and logical S3 keys. Optimized for single-digit millisecond retrieval. |

## 3. Media Processing Pipeline

| Resource | Logical ID / Name | Role in the System |
| :--- | :--- | :--- |
| **ECS Fargate** | `TranscodeTask` | The "Heavy Lifter." A serverless container engine that runs our FFmpeg Docker image. It is optimized with 4 vCPUs for near-real-time HLS transcoding. |
| **S3 (Source)** | `MediaSourceBucket` | The "Ingestion Bay." Accepts raw MP4 uploads and triggers the automated transcoding event chain via EventBridge. |
| **S3 (HLS)** | `HlsOutputBucket` | The "Archive." Stores the professional HLS artifacts (Segments and Manifests) generated by the Fargate transcoder. |
| **SQS** | `TranscodeQueue` | The "Buffer." Decouples S3 uploads from Fargate processing, ensuring no transcoding tasks are lost during high-volume upload spikes. |
| **EventBridge** | `S3UploadRule` | The "Announcer." Listens for new file uploads and routes them to the SQS queue, breaking circular dependencies between infrastructure stacks. |

## 4. Release & Build (CI/CD)

| Resource | Logical ID / Name | Role in the System |
| :--- | :--- | :--- |
| **CodePipeline** | `StreamingPipeline` | The "Conductor." A self-mutating pipeline that automates the entire lifecycle—from Git push to global deployment. |
| **CodeBuild (Android)**| `BuildAndroidApp` | The "Compiler." A high-power server that installs the Android SDK, accepts licenses, and compiles the project into a production APK. |
| **CodeBuild (Asset)** | `Assets` (CDK Managed) | The "Image Factory." Automatically builds the FFmpeg Docker image and pushes it to ECR as part of the pipeline run. |
| **ECR** | `media-transcoder` | The "Registry." A private repository storing the immutable Docker images used by the Fargate transcoder. |
| **S3 (Cache)** | `AndroidSdkCacheBucket` | The "Memory." A persistent cache that stores the 1.5GB Android SDK to reduce build times by 40% on subsequent runs. |

## 5. Observability

| Resource | Logical ID / Name | Role in the System |
| :--- | :--- | :--- |
| **CloudWatch Dashboard**| `Modular-Overview` | The "Mission Control." A unified visual interface for monitoring system health, API errors, and video playback trends (Top 10 leaderboard). |
| **Log Groups** | `GetCatalog/LogPlay/Transcoder`| The "Audit Trail." Stores detailed execution logs for all serverless components, essential for root-cause analysis and performance tuning. |
